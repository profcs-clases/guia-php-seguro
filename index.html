Módulo 1: Anatomía de un Proyecto PHP Profesional

Olvida el "todo en un solo archivo". Un proyecto real requiere separación de responsabilidades, mantenibilidad y un punto de entrada único.

1.1 El Patrón Front Controller

Todas las solicitudes HTTP pasan por un único archivo (public/index.php). Este archivo inicializa la configuración, la conexión a la base de datos y enruta la petición al controlador adecuado.

// public/index.php
require_once __DIR__ . '/../config/config.php';
require_once __DIR__ . '/../app/Models/Database.php';

// Enrutamiento básico
$uri = parse_url($_SERVER['REQUEST_URI'], PHP_URL_PATH);
// ... lógica de router ...

1.2 Estructura de Carpetas Recomendada

  • /public: Único directorio accesible desde la web. Contiene index.php, CSS, JS e imágenes.
  • /app: Lógica de la aplicación. Nadie debe acceder aquí directamente vía web.
    • Controllers/: Reciben la petición, validan datos y llaman al Modelo.
    • Models/: Entidades y lógica de acceso a datos (CRUD).
    • Views/: Archivos .php o .twig con HTML puro (sin lógica de negocio).
  • /config: Variables de entorno y configuración global.
  • /storage: Logs de errores y archivos subidos por usuarios (fuera de /public).

1.3 Convenciones PSR

PSR-1: Las clases usan UpperCamelCase, los métodos lowerCamelCase.
PSR-4: Autoloading. La estructura de carpetas debe reflejar los Namespaces. Ej: App\Models\User vive en app/Models/User.php.
